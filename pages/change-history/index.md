# Change History

Change history helps adopters understand what changed, who is affected, and whether an integration requires action.

The current source-backed history covers [Hypercerts Lexicon releases](/reference/releases). Future entries should connect changes in protocol meaning and guidance to the affected Lexicons, SDK, APIs, and services.

## Change entry structure

Each adopter-facing entry should include:

- the date and affected contracts or component versions;
- a concise description of what changed;
- compatibility impact and who is affected;
- required migration steps, or an explicit statement that no action is required;
- links to changed Guide and Reference pages;
- links to the independent source releases and changelogs.

Coordinated protocol packaging is still evolving. Change entries must not imply a universal conformance version or combine independent component releases into one version unless that release relationship has been explicitly established.
